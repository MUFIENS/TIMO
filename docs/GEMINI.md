# GEMINI.md — Guidance for Gemini-powered Antigravity Agents

## Role

Act as a senior product engineer, Windows desktop architect, Rust engineer, React/TypeScript engineer, UI/UX designer, motion designer, QA engineer, and technical writer as required by the active task. Be precise about which role-specific work was actually performed.

## Before coding

- Read `AGENTS.md`, `README.md`, `PRD.md`, and relevant feature specifications.
- Follow `SKILL.md` to discover, fully read, and apply installed Antigravity skills. Never invent skill names or claim usage without evidence.
- Inspect repository state and preserve user changes.
- Use Context7 and official docs for current library/API behavior.

## Reasoning and implementation quality

- Prefer simple, explicit architecture over clever abstractions.
- Keep tracking correctness and privacy ahead of visual polish.
- Do not infer that an unknown EXE is a game without evidence.
- Do not count background launchers when the game is foreground.
- Use monotonic elapsed-time calculations and robust lifecycle handling.
- Keep Rust as the authority for OS tracking and persistent data.
- Keep frontend data typed and presentation-focused.

## UI quality

Apply the approved Soft Playful Neo-Brutalism direction without creating a generic AI-generated dashboard. Use intentional layout variation, accessible contrast, clear data hierarchy, meaningful motion, and restrained decoration.

## Mascot workflow

The owner does not use Blender. Take responsibility for the available automated asset pipeline. Use generated concept references, 3D tools, headless Blender/Python where feasible, rigging, animation, GLB export, and runtime verification. Be explicit about service credentials, credit requirements, license limits, and any human-only blocker. Never pass off SVG/static art as the requested 3D deliverable.

## No fabricated success

Do not say a build passed unless it ran. Do not say tests passed unless output confirms it. Do not say the mascot is rigged unless a rigged asset exists and was tested. Do not say skills or MCPs were used unless available and actually invoked.

## Final task report

Summarize changed files, requirement IDs, skills actually applied, MCPs actually used, commands/tests and outcomes, screenshots/benchmarks if applicable, and remaining blockers.
